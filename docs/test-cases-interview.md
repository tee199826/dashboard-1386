# Test Case — ระบบบันทึกแบบซักผู้เสพ

ครอบคลุมหน้า `/intel/interview/new` (บันทึกข้อมูลผู้เสพ) และ `/intel/interview` (ค้นหา/รายการที่บันทึก)
รวมถึงตาราง `interview_records` / `interview_records_pii` และ trigger ที่ออกเลขอัตโนมัติ

---

## เตรียมก่อนทดสอบ

| # | สิ่งที่ต้องมี | วิธีตรวจ |
|---|---|---|
| 1 | รัน `supabase/migrations/20260910_interview_records.sql` แล้ว | Supabase → Table Editor เห็นตาราง `interview_records` และ `interview_records_pii` |
| 2 | รัน `supabase/migrations/20260911_interview_doc_no.sql` แล้ว | `interview_records` มีคอลัมน์ `doc_no`, `interview_records_pii` มีคอลัมน์ `friend_address` |
| 2b | รัน `supabase/migrations/20260912_interview_seq_lock.sql` แล้ว | จำเป็นสำหรับ D-08 (บันทึกพร้อมกันแล้วเลขต้องไม่ชนกัน) |
| 3 | บัญชีผู้ดูแลระบบ (`profiles.role = 'admin'`) | ล็อกอินแล้วเห็นหมวด **ฐานข้อมูลการข่าว** ในแถบด้านข้าง |

| 5 | เบราว์เซอร์เปิด DevTools ไว้ | ใช้ดู Console / Network ตอนเทสต์ข้อผิดพลาด |

> ⚠️ ข้อมูลที่บันทึกระหว่างเทสต์เป็นข้อมูลจริงในฐานข้อมูล — ใช้ชื่อสมมติ และลบทิ้งเมื่อเทสต์เสร็จ

### B.1 ช่องบังคับแบบมีเงื่อนไข

| รหัส | สิ่งที่ทดสอบ | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| B-10 | "อื่นๆ" → ต้องระบุ | ส่วนที่ ๑ เลือก **จบการศึกษา = อื่นๆ** | มีช่อง "ระบุระดับการศึกษา" โผล่ขึ้นมา พร้อม `*` และนับเป็นช่องบังคับเพิ่ม |
| B-11 | ยกเลิก "อื่นๆ" | ต่อจาก B-10 เปลี่ยนไปเลือกระดับอื่น | ช่อง "ระบุ" หายไป และไม่นับเป็นช่องที่ขาดอีก |
| B-12 | เสพเป็นกลุ่ม → ต้องระบุจำนวนคน | ข้อ ๓ เลือก **ลักษณะการเสพครั้งแรก = เสพเป็นกลุ่ม** | ช่อง "เสพเป็นกลุ่ม ครั้งละประมาณ (คน)" เปิดให้กรอก และกลายเป็นช่องบังคับ |
| B-13 | เสพคนเดียว → ปิดช่องจำนวนคน | ข้อ ๓ เลือก **เสพคนเดียว** | ช่องจำนวนคนถูกปิด (เทา กรอกไม่ได้) และไม่บังคับ |
| B-14 | เสพต่อ → ต้องระบุระยะเวลา | ข้อ ๓ เลือก **หลังจากเสพครั้งแรก = เสพต่อ** | ช่อง "เสพต่อนาน (ปี/เดือน)" เปิดและบังคับกรอก |
| B-15 | ใช้ชนิดเดียว → ไม่ต้องระบุยาที่ใช้ร่วม | ข้อ ๔ เลือก **ลักษณะการใช้ยา = ใช้ชนิดเดียว** | ช่อง "ระบุยาที่ใช้ร่วม/สลับ" ถูกปิดและไม่บังคับ |
| B-16 | ใช้ร่วม/สลับ → ต้องระบุ | ข้อ ๔ เลือก **ใช้ร่วมกับยาอื่น** | ช่อง "ระบุยาที่ใช้ร่วม/สลับ" เปิดและบังคับ |
| B-17 | สถานที่เสพ "อื่นๆ" | ข้อ ๔ ติ๊ก **สถานที่ใช้เสพ = อื่นๆ** | ช่อง "ระบุสถานที่/บริเวณ" เปิดและบังคับ |
| B-18 | แหล่งที่ซื้อได้ประจำ | ข้อ ๖ ไม่กรอกแถวแหล่งซื้อเลย → กดบันทึก | หัวข้อ "แหล่งที่ซื้อได้ประจำ" เป็นสีแดง ขึ้นว่า "กรุณาเพิ่มอย่างน้อย 1 แหล่ง และระบุพื้นที่" |
| B-19 | แหล่งซื้อ กรอกช่องใดช่องหนึ่งก็ผ่าน | ข้อ ๖ กรอกเฉพาะ "บริเวณ/สถานที่" ช่องเดียว | ผ่าน ไม่ขึ้นแดงแล้ว |

| D-02 | เลขแรกของระบบ | ตารางว่าง → บันทึกรายการแรก | ได้ เลขที่แบบ `๑-๑/๐๐๐๑` และ รหัสอ้างอิง `ผส-69-0001` (ปีงบ 2569) |
| D-03 | เลขเดินต่อ | บันทึกรายการที่ 2 และ 3 | ได้ `๑-๑/๐๐๐๒`, `๑-๑/๐๐๐๓` ตามลำดับ |

| D-05 | ชนิดตัวเลขของแต่ละชุด | ดูเลขที่ได้ | **เลขที่แบบเป็นเลขไทย** (`๑-๑/๐๐๐๑`) แต่ **รหัสอ้างอิงเป็นเลขอารบิก** (`ผส-69-0001`) |
| D-06 | ปีงบข้ามปี | ตั้งวันที่สัมภาษณ์เป็น `2026-10-01` → บันทึก | `code` ขึ้นปีงบใหม่ (`ผส-70-0001`) แต่ `doc_no` **เดินต่อไม่รีเซ็ต** |

| D-08 | บันทึกพร้อมกัน | เปิด 2 แท็บ กรอกครบทั้งคู่ → กดบันทึกพร้อมกัน | ได้คนละเลข ไม่ซ้ำกัน ทั้งสองแท็บบันทึกสำเร็จ |

## I. กรณีผิดพลาด

| รหัส | สิ่งที่ทดสอบ | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| I-01 | ยังไม่ได้รัน migration | เปิด `/intel/interview` ก่อนรัน SQL | ขึ้น **"ยังไม่ได้สร้างตารางของแบบซักผู้เสพ"** พร้อมบอกชื่อไฟล์ที่ต้องรัน |
| I-02 | เน็ตหลุดตอนบันทึก | กรอกครบ → ปิด Wi-Fi → กดบันทึก | ขึ้น "บันทึกไม่สำเร็จ: ..." และ**ข้อมูลในฟอร์มยังอยู่ครบ** ไม่หาย |
| I-03 | กดบันทึกซ้ำรัว ๆ | กดปุ่มบันทึกรัว ๆ ตอนกำลังบันทึก | ปุ่มเปลี่ยนเป็น "กำลังบันทึก..." และกดไม่ได้ — ต้องได้แถวเดียว ไม่ใช่หลายแถว |
| I-04 | ปุ่มกดได้ตลอด | ดูปุ่มบันทึกตอนยังกรอกไม่ครบ | ปุ่ม**กดได้** (ไม่เทา) แต่กดแล้วขึ้นเตือนแทนการบันทึก |
| I-05 | กดซ้ำหลังบันทึกสำเร็จ | บันทึกสำเร็จ → รีบกดปุ่มบันทึกซ้ำภายใน 3 วินาทีก่อนเด้งหน้า | ปุ่ม**เทา กดไม่ได้** — ต้องไม่เกิดแถวที่สองในฐานข้อมูล |
| I-06 | PII ล้มเหลว → ย้อนรายการ | Supabase: `revoke insert on interview_records_pii from authenticated;` → กรอกครบ → บันทึก → คืนสิทธิ์ด้วย `grant insert ...` | ขึ้น "บันทึกไม่สำเร็จ ... ยกเลิกรายการนี้แล้ว" และ **`interview_records` ต้องไม่มีแถวค้าง** |
| I-07 | กดบันทึกใหม่หลัง I-06 | ต่อจาก I-06 (คืนสิทธิ์แล้ว) กดบันทึกอีกครั้ง | บันทึกสำเร็จ ได้ **1 แถว** ไม่ใช่ 2 |
